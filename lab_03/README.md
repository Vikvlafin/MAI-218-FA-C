# Фундаментальные алгоритмы. Лабораторная №3

Сборка в Linux или WSL с GCC. Запустите из каталога лабораторной.

~~~sh
sh build.sh /tmp/fa3
~~~

В каждой задаче отдельная программа. В примерах ниже имя task_01 означает
файл /tmp/fa3/task_01. Интерактивные команды можно вводить по одной или подать
из текстового файла на stdin. Команда quit завершает сеанс. Неверная команда
сообщает ошибку на stderr. Некорректный исходный файл приводит к ненулевому
коду завершения.

## 01. Перевод основания

Команда запуска — task_01 -255 4 → -FF. Первый аргумент — десятичная запись с необязательным
знаком и модулем до UINT64_MAX. Второй — r от 1 до 5. Ответ в основании 2^r,
буквы заглавные, ведущих нулей нет. Разбор десятичной строки отделён от
преобразования. Функция convert выделяет группы битов и записывает цифры без обычной
арифметики.

## 02. Расписание

Запуск без аргументов. На stdin первая строка n k, затем n строк
id HH:MM HH:MM. stdout содержит одно число. Доклады идут по времени окончания.
Для каждого используется зал с самым поздним допустимым освобождением.
Время в минутах позволяет хранить число свободных залов по каждой минуте дня.

~~~text
4 1
1 00:00 00:05
2 00:00 00:02
3 00:02 00:05
4 00:05 00:06
~~~

Ответ — 3.

## 03. Хаффман

Команда запуска — task_03 input.bin. Сначала идут строки «байт частота код» в порядке
возрастания байта, затем ORIGINAL_BYTES, ENCODED_BITS, ENCODED_BYTES, SAVING.
Оценка учитывает только закодированные биты, без метаданных. Частоты считаются
потоком, дерево строится собственной бинарной минимальной кучей. Для одного
различного байта код 0. Для пустого файла все итоговые показатели равны нулю.

## 04. Почта

Запуск task_04 string демонстрирует операции String. Обычный запуск без аргументов
принимает первой строкой office город улица дом корпус квартира индекс.
Имена города и улицы вводятся одним полем, пустой корпус обозначается дефисом.

~~~text
office Town Road 1 - 1 999999
add City Street 2 - 3 500000 00000000000002 1.5 02:01:2000 00:00:00 03:01:2000 00:00:00 -
list
find 00000000000002
overdue
remove 00000000000002
quit
~~~

После адреса в add идут 14-значный ID, вес, создание, срок доставки, фактическое
вручение. Время записывается двумя полями dd:MM:yyyy hh:mm:ss. Дефис вместо
фактического времени означает отсутствие вручения. Отдельный срок доставки —
согласованное инженерное соглашение. Просрочка означает, что срок невручённой
посылки уже прошёл по локальному системному времени. list выводит основной порядок
по индексу и ID. delivered и overdue выводят соответствующие отправления в порядке создания.

## 05. Студенты

Команда запуска — task_05 students.txt trace.txt. Порядок полей в строке показан ниже.
id имя фамилия группа оценка1 оценка2 оценка3 оценка4 оценка5.
Оценки 0–255, повторяющиеся ID разрешены. Доступны следующие команды.

- find id 10, find name Ann, find surname Smith, find group A.
- sort id, sort name, sort surname, sort group. list показывает текущий порядок.
- trace 10 пишет данные всех совпадений в trace. above пишет фамилии и имена студентов
  выше среднего по всему исходному списку. Порог сравнивается точно по целым суммам
  пяти оценок. Trace открывается заново на сеанс после проверки идентичности файлов.

## 06. Транспорт

Команда запуска — task_06 stop1.txt stop2.txt … . В каждом файле первая строка x y,
затем записи «номер dd.MM.yyyy hh:mm:ss dd.MM.yyyy hh:mm:ss S|I|E». S — начало
рейса, I — промежуточная остановка, E — конец. Времена в локальной календарной шкале.
Записи сортируются по номеру и временам, затем собираются в связный список рейсов
со связными списками остановок. Рейс может начинаться в тот же момент, когда закончился
предыдущий. Если несколько записей имеют одинаковые обе метки времени, выбирается
порядок, совместимый с открытым рейсом. При одинаковых временах и маркере
используется лексикографический порядок путей файлов остановок. Это соглашение
обеспечивает одинаковый результат при перестановке тех же файлов; порядок
проезда при совпадении меток из входных данных восстановить невозможно.

Команды routes max|min, path max|min, route max|min, stop max|min, idle max.
Расстояние евклидово в единицах координат. Путь — сумма длин рейсов транспорта,
route — экстремальная длина одного рейса. stop и idle считаются в секундах,
idle суммирует стоянки. При равенстве допустим любой победитель.

## 07. Жители

Команда запуска — task_07 people.txt. Порядок полей в строке показан ниже.
фамилия имя отчество dd.MM.yyyy M|W доход. Пустое отчество — дефис.
list показывает присвоенные сеансовые номера и данные в порядке от младших к старшим.
Поиск принимает один или несколько фильтров, например find sex W surname Smith.
Ключи поиска — surname, name, patronymic, birth, sex, income. Доход сравнивается с допуском 1e-9.

add принимает полную запись, edit — номер и полную новую запись, remove — номер.
save путь сохраняет данные в исходном формате без сеансовых номеров.
undo откатывает последние floor(N/2) успешных изменений, после чего начинает
новую серию. При N=0 или 1 изменений для отката нет.

## 08. Многочлены

Команда запуска — task_08 commands.txt. Пример командного файла.

~~~text
Mult(x^2+3x-1,2x+x^3);
Add(4x-8);
Eval(1);
Div(x^5,x^2-1);
~~~

Команды чувствительны к регистру. Поддерживаются Add, Sub, Mult, Div, Mod, Eval, Diff, Cmps.
Комментарий до конца строки начинается с %, блочный ограничен [ и ], без вложенности.
У двоичных операций один аргумент означает «аккумулятор — левый операнд».
Eval(точка) использует аккумулятор, Eval(многочлен,точка) — явный многочлен.
Обе формы печатают значение, не меняя аккумулятор.
Diff() дифференцирует аккумулятор, Diff(многочлен) — явный аргумент.
Остальные вычисленные многочлены сохраняются в аккумулятор, изначально нулевой.

Коэффициенты и точка Eval — int64_t, степени — unsigned. Поддерживаются x,
необязательное умножение коэффициента через *, степень через ^, пробелы между токенами.
Div/Mod используют деление в Z[x]. Если шаг требует нецелого коэффициента,
команда завершается ошибкой. Переполнение промежуточного результата также
считается ошибкой. После ошибки обработка командного файла прекращается.

## 09. Слова и BST

Команда запуска — task_09 input.txt ' ' ',' . Каждый разделитель задаётся одним байтом.
Набор задаётся полностью через CLI, без автоматического добавления пробелов или LF.
Слова сравниваются побайтово с учётом регистра. Доступны следующие команды. find слово, list, top n,
shortest, longest, depth, save путь, load путь. В find весь остаток строки после
первого пробела считается искомым словом. Если n больше числа слов, top печатает все.
Для слова с переводом строки или другими управляющими байтами есть find-hex.
Например, find-hex 610a62 ищет три байта «a», LF, «b».

Глубина — число уровней, 0 для пустого дерева. Сериализация хранит частоту, длину
и байты слова в прямом обходе. Вставка уникальных ключей в таком порядке
восстанавливает исходную форму BST. При загрузке проверяются порядок обхода и
совместимость слов с текущими разделителями. Неудачная загрузка оставляет прежнее дерево.

## 10. Деревья скобочных выражений

Команда запуска — task_10 expressions.txt trees.txt. Пример входной строки.
A(B(E(G,T,R(W,Z)),F(L,M)),C). Каждый узел печатается с отступом два пробела
на уровень, между деревьями пустая строка. Метка — непустая последовательность
без пробелов, запятых и скобок. Детей может быть сколько угодно. Разбор
построчный, без рекурсии. Выход не может указывать на входной файл.
