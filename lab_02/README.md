# Лабораторная №2 — фундаментальные алгоритмы

C11, GCC, Linux/WSL. В каждом `task_XX`: `functions.h` — интерфейс,
`functions.c` — обработка данных, `main.c` — запуск и демонстрация.

Из каталога `lab_02`:

```sh
sh build.sh /tmp/fa2-bin
sh build.sh /tmp/fa2-san san
```

Сборка: `-std=c11 -Wall -Wextra -Wpedantic -Werror`. Режим `san` добавляет
AddressSanitizer и UndefinedBehaviorSanitizer. Исполняемые файлы создаются
в указанном каталоге, вне сдаваемых исходников.

## Запуск

|Задача|Пример|Результат|
|---|---|---|
|01|`/tmp/fa2-bin/task_01 -r abc`|`cba`|
|02|`/tmp/fa2-bin/task_02 input.txt -a output.txt`|Отсортированные сотрудники в файле|
|03|`/tmp/fa2-bin/task_03 aba file1.txt file2.txt`|Все начала вхождений: строка и столбец с 1|
|04|`/tmp/fa2-bin/task_04 < files.txt`|Оптимальный набор для резервного копирования|
|05|`/tmp/fa2-bin/task_05`|Демонстрация расширенного вывода|
|06|`/tmp/fa2-bin/task_06`|Демонстрация чтения строки и файла|
|07|`/tmp/fa2-bin/task_07`|Все максимальные векторы для каждой из трёх норм|
|08|`/tmp/fa2-bin/task_08 16 FFFF 1`|`10000`|
|09|`/tmp/fa2-bin/task_09`|Конечность записей 0.1, 0.125, 0.5 в основании 2|
|10|`/tmp/fa2-bin/task_10`|Коэффициенты 49, 62, 27, 4 при a=2|

В задачах 05–10, кроме дополнительного режима 08, используются встроенные
демонстрационные данные. Произвольные данные можно передать функциям через их
интерфейсы. Количество variadic-аргументов и их C-типы должны точно соответствовать
прототипу; проверить отсутствующие аргументы средствами C невозможно.

## Условия и интерфейсы

01. Поддерживаются `-l`, `-r`, `-u`, `-n`, `-c`. Для `-c`:
`task_01 -c first seed [other ...]`, seed — десятичное число 0..UINT_MAX.
Символы обрабатываются как байты в локали C; UTF-8 не декодируется.
Перемешиваются целые строки, затем объединяются без разделителей. Одинаковый seed
в одной реализации libc даёт одинаковый порядок; между разными libc он может отличаться.

02. Строка сотрудника: `id name surname salary`. id — неотрицательное целое,
имя и фамилия — непустые латинские буквы, зарплата — конечное неотрицательное
десятичное число (разрешена экспонента). Флаги: `-a`, `/a`, `-d`, `/d`.
Четыре ключа: зарплата, фамилия, имя, id; сортирует `qsort`.
Параметр epsilon функции чтения задаёт интервалы зарплат шириной epsilon:
ключ зарплаты — `floor(salary / epsilon)`. Внутри интервала используются следующие
ключи. Это даёт транзитивный порядок, необходимый `qsort`; в демонстрации epsilon=1e-9.
Входной и выходной пути должны обозначать разные файлы. Проверяются идентификаторы
уже открытых файлов через fstat; выход открывается без предварительного усечения,
а усечение обычного файла выполняется только после проверки. Совпадающие пути,
жёсткие и символические ссылки на вход отклоняются без изменения входа.

03. `search_files(substring, &results, count, paths...)` ищет все вхождения,
включая перекрывающиеся. Алгоритм Кнута–Морриса–Пратта, время O(длина подстроки +
суммарная длина файлов), память O(длина подстроки + число совпадений).
Файлы читаются потоком; для определения начала вхождения хранится кольцевой массив
координат последних символов, размер которого равен длине подстроки.
Пустая подстрока отклоняется. LF начинает новую строку, остальные байты, включая
TAB и CR, занимают один столбец. Переводы строк в подстроке разрешены.
Результат освобождает `free_search`; пути остаются собственностью вызывающего кода.

04. Вход: `n capacity`, далее ровно n строк `filename size importance`.
n и size положительные; capacity и importance неотрицательные; имена уникальны.
Динамическое программирование решает задачу 0/1 точно. Время и память O(n*capacity),
поэтому очень большая вместимость может потребовать слишком много памяти.
Вывод: `TOTAL_SIZE S`, `TOTAL_IMPORTANCE I`, `FILES k`, затем k имён в исходном порядке.
`BackupResult.files` — новый массив с заимствованными именами; его освобождает вызывающий код.

05–06. Сигнатуры соответствуют printf/scanf. Стандартные спецификаторы C11
передаются libc, расширенные обрабатываются отдельно. Поддерживаются стандартные
ширины, точности и модификаторы длины, ввод со scanset и подавлением присваивания.
POSIX-позиционные аргументы и нестандартные расширения libc не поддерживаются.
Для `%Ro` принят диапазон 1..3999 и каноническая римская запись;
`%Zr` использует числа Фибоначчи 1,2,3,5,..., младший коэффициент слева,
единицу окончания справа; ноль записывается `01`.
`%Cv`/`%CV` принимают int и основание при выводе, int* и основание при вводе;
`%to`/`%TO` — строку и основание. Основание вне 2..36 заменяется на 10.
`%mi`/`%mu` требуют 4-байтового int/unsigned int, `%md` получает double,
`%mf` — float, переданный по правилам variadic как double. Дамп показывает
8 бит каждого байта в порядке адресов, байты разделены одним пробелом.
`oversprintf` имеет интерфейс sprintf без параметра размера: достаточность буфера
обеспечивает вызывающий код, переполнение означает неопределённое поведение.
Для scanf строковые
назначения должны иметь достаточный размер, рекомендуется задавать ширину.
Возврат: число записанных символов или -1; для ввода — число присваиваний либо EOF.
Ошибки буферизованного вывода дополнительно проверяются через fflush/fclose.

07. `Vector` хранит указатель на n координат. `NormSpec` содержит универсальный
указатель на функцию нормы и контекст: для Lp — адрес p>=1, для матричной нормы —
массив n*n элементов по строкам. Матрица проверяется на симметричность и положительную
определённость разложением Холецкого. Норма равна `sqrt((Ax,x))`.
`longest_vectors(n, epsilon, &results, norm_count, vector_count, vectors..., specs...)`
принимает структуры по значению. Возвращаются все векторы на расстоянии не более
epsilon от максимальной нормы. `free_norm_results` освобождает массивы результатов,
но не исходные координаты, которые должны оставаться доступны.

08. `sum_numbers(base, &result, count, strings...)` складывает неотрицательные
целые любой длины, используя `add_numbers` — сложение в столбик.
Основания 2..36, буквы обоих регистров, выход в верхнем регистре без ведущих нулей.
Пустая сумма равна 0; пустая строка числа и знаки не допускаются.

09. `finite_fractions(base, &result, count, doubles...)` возвращает массив 0/1.
Принятое и согласованное с пользователем допущение (подтверждения преподавателя нет):
кратчайшая десятичная запись с обратным преобразованием в тот же double,
а не точная двоичная дробь, хранящаяся в памяти. Например, 0.1 конечно в основании 10,
но бесконечно в основании 2. Из сокращённого знаменателя должны исключаться все
простые множители основания. Для десятичной записи достаточно проверить остаточные
множители 2 и 5. Основание — int >=2, дроби строго между 0 и 1; локаль C.

10. `shift_polynomial(epsilon, a, &result, degree, f0, ..., fn)` получает
коэффициенты от младшей степени к старшей и возвращает g0,...,gn в таком же порядке.
Используется схема Горнера для замены x=(x-a)+a, O(n²) времени и O(n) памяти.
epsilon положительное, значения конечные. Отслеживаются переполнение и локальная
ошибка округления в double относительно epsilon*max(1,abs(value)); это не доказательство
суммарной ошибки всего многочлена. Малые ненулевые коэффициенты сохраняются.

Обычные обрабатывающие функции возвращают 0 при успехе, ненулевой код при ошибке:
1 — аргументы/данные, 2 — память, 3 — ввод-вывод либо численный диапазон в зависимости
от задачи. Динамический результат освобождает вызывающий код после успешного вызова.
Функции освобождения также возвращают статус: 0 при успехе, 1 при NULL с ненулевым count;
NULL с count=0 допускается. Передавать можно только принадлежащий вызывающему коду
результат успешного вызова соответствующей функции и фактическое число элементов.
